# 카카오톡 iOS `.ktheme` 개발 전체 흐름 (한국어 · 기술 전용)

> 이 문서는 디자인 판단을 하지 않는다. 색/그림/아이콘의 모양은 사용자와 별도 AI가 정한다.
> 과거 카카오 공식 문서(2018)와 최신 커뮤니티 샘플(2026)의 구조가 다를 수 있으므로 **실제 출발점으로 사용하는 샘플 버전**을 우선한다.

## 0. 개발 개념

- iOS 테마는 일반적인 Safari 웹페이지가 아니다. `KakaoTalkTheme.css`의 선택자 및 `-ios-*`, `-kakaotalk-*` 키는 카카오톡이 해석하는 **전용 테마 문법**이다.
- 브라우저 CSS 규칙을 임의로 붙인다고 카카오톡 레이아웃이 바뀌지 않는다. 앱이 노출한 테마 가능 범위 밖으로 확장할 수 없다.
- 디자인 파일을 만들거나 채색하는 MCP가 아니라, **파일 계약·규격·레퍼런스·검증·패키징**을 다루는 MCP다.

## 1. 기준 샘플을 확보한다

1. 사용자가 실제로 적용할 iOS 카카오톡의 앱 버전을 확인한다.
2. 해당 버전에 가장 가까운 정상 작동 `.ktheme` 또는 소스 샘플을 확보한다. 권리를 확인한 샘플만 사용한다.
3. 샘플 ZIP의 루트에 `KakaoTalkTheme.css`와 `Images/`가 있는지 확인한다.
4. CSS 선택자, 속성 이름, 이미지 참조 베이스명을 추출한다.
5. 공식 자료가 구형 선택자 `NavigationBarStyle1-V4`와 `KakaoTalk.css`를 썼다는 사실을 기록하고, 이를 현대 파일과 섞지 않는다.

## 2. 파일 구조

```text
MyTheme/
├── KakaoTalkTheme.css
└── Images/
    ├── commonIcoTheme.png            # 예: 2018 공식 가이드는 162×162px
    ├── maintabIcoFriends@2x.png      # 파일명은 사용 중인 실제 샘플 기준
    ├── maintabIcoFriends@3x.png
    └── ...
```

완성본 `.ktheme`은 ZIP 컨테이너이며, 아카이브 내부 경로가 다음처럼 시작해야 한다:

```text
KakaoTalkTheme.css
Images/commonIcoTheme.png
Images/maintabIcoFriends@2x.png
```

`MyTheme/KakaoTalkTheme.css`처럼 외부 폴더가 한 겹 들어가는 패키지는 피한다. `__MACOSX`, `.DS_Store`, `._*`는 제거한다.

## 3. 기본 메타데이터

```css
ManifestStyle {
  -kakaotalk-theme-id: 'com.example.theme.unique_id';
  -kakaotalk-theme-name: '사용자가 정한 테마명';
  -kakaotalk-theme-version: '1.0.0';
  -kakaotalk-theme-url: 'https://example.org';
  -kakaotalk-author-name: '사용자가 정한 이름';
}
```

- 고유 ID가 다른 테마와 충돌하지 않게 한다.
- 버전업 시 앱이 기존 파일을 새 버전으로 취급하는지 실기기 확인한다.
- 메타데이터 문법은 현재 샘플을 우선하고 예시를 맹신하지 않는다.

## 4. 사용자 에셋 연결

1. 사용자가 제공한 PNG를 `Images/`에 넣는다.
2. CSS의 각 이미지 속성에 **정확한 베이스 파일명**을 연결한다. 예를 들어 `'chatroomBgImage.png'`를 참조하면 실제 파일은 `chatroomBgImage@2x.png`, `@3x.png`일 수 있다.
3. @2x와 @3x는 동일 시각 요소의 해상도 쌍이다. 2x가 200×100이면 3x는 300×150 픽셀이어야 한다(일반적인 2:3 쌍 기준).
4. 말풍선 이미지의 stretch/cap inset은 사용한 샘플과 원본 PNG의 픽셀 구조에 맞게 조정한다. 디자인 자체를 바꾸는 것이 아니라 **늘어나는 영역의 기술적 안정성**을 맞춘다.
5. 아이콘 normal/selected 상태 등은 CSS 키가 실제 가리키는 파일을 기준으로 누락을 점검한다.

## 5. AI 바이브 코딩 워크플로

1. `ktheme_engineering_only` 프롬프트를 적용한다.
2. `read_ktheme_doc("CSS-기술명세")`로 기준 문법을 읽는다.
3. `create_ktheme_skeleton` 또는 이미 가진 샘플을 시작점으로 사용한다.
4. 사용자가 그림과 색을 결정할 때까지 디자인 관련 판단은 보류한다.
5. `inspect_ktheme_project`로 현재 참조와 선택자 목록을 확인한다.
6. `validate_ktheme_project`로 정적 오류를 제거한다.
7. `package_ktheme`으로 `.ktheme`을 만든다.
8. `validate_ktheme_archive`로 압축 파일을 다시 검사한다.
9. 사용자가 iOS 카카오톡에 직접 적용해 친구목록/채팅방/말풍선/입력창/상태별 탭을 확인한다.
10. 앱 버전·에러·화면별 결과를 기록해 회귀 테스트한다.

## 6. 설치 테스트

- 현재 이용 환경에서 파일을 iPhone에 전달한다(카카오톡 나와의 채팅이나 파일 공유 등).
- `.ktheme` 파일을 카카오톡에서 열어 테마 목록에 추가하고 적용한다.
- 실패하면 ZIP 루트 구조 → 메타데이터 → CSS/이미지 참조 → 앱 버전·적용 경로 순으로 점검한다.
- 앱 UI 메뉴명·공유 경로는 iOS/카카오톡 업데이트에 따라 달라질 수 있다.

## 7. 성공 수준 구분

- **정적 검사 통과**: 폴더·참조·PNG·ZIP의 기계적 일관성만 확인.
- **실기기 설치 통과**: 사용자가 특정 앱 버전에서 테마 가져오기 완료.
- **화면 적용 통과**: 기기 스크린샷/실사용으로 각 화면의 CSS 키 동작 검증.

정적 검사 통과만으로 "완전 호환" 또는 "설치 확인"이라고 선언하지 않는다.
