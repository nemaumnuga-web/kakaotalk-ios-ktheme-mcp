# 에셋 기술 규격 / `.ktheme` 패키징

## 1. 이미지 파일 검사

- PNG 시그니처: `89 50 4E 47 0D 0A 1A 0A`.
- `IHDR` 청크 너비/높이를 검사한다. 확장자만 `.png`로 바꾼 JPEG는 오류다.
- 파일명 대소문자와 `@2x`, `@3x` 접미사를 정확히 지킨다.
- 에셋의 색·내용·스타일은 사용자와 디자인 AI가 만든다.
- 이 MCP가 PNG 내용을 이미지로 생성하거나 수정하지 않는다.
- 리스트 아이콘 `commonIcoTheme.png`의 162×162px은 2018 공식 명세의 수치이며 최신 샘플에서는 실제 리소스를 확인해야 한다.

## 2. CSS 참조 방식

`-ios-background-image: 'chatroomBgImage.png';` → `Images/chatroomBgImage@2x.png`, `Images/chatroomBgImage@3x.png` 같은 물리 에셋을 참조하는 샘플이 있다. 참조명 자체에 `Images/` 경로나 `@2x`를 추가하면 샘플의 해석과 달라질 수 있다.

## 3. 압축 패키지 내부 구조

```text
mytheme.ktheme (ZIP container)
├── KakaoTalkTheme.css
└── Images/
    ├── commonIcoTheme.png
    ├── chatroomBgImage@2x.png
    └── chatroomBgImage@3x.png
```

잘못된 예: `mytheme.ktheme/MyTheme/KakaoTalkTheme.css`처럼 중첩된 루트.

## 4. CLI 대신 MCP 호출 흐름

1. `validate_ktheme_project({"theme_dir":"/path/theme"})`
2. 경고를 읽고 사용자 에셋과 CSS를 교정
3. `package_ktheme({"theme_dir":"/path/theme","output_path":"/path/out/theme.ktheme","fail_on_warnings":false})`
4. `validate_ktheme_archive({"ktheme_path":"/path/out/theme.ktheme"})`

패키징은 입력 `KakaoTalkTheme.css` + `Images/*.png`만 수록하며, ZIP 항목은 정렬/고정 timestamp로 재현성이 있다. `.DS_Store`와 폴더 외 파일은 제외한다. 원본 CSS·PNG는 변경하지 않는다. 결과물은 현재 권한 내 출력 경로에 생성한다.

## 5. 리소스/보안

- 파일 접근은 `cwd`, 임시 디렉터리, `KTHEME_ALLOWED_ROOTS` 범위에 한정한다.
- 심볼릭 링크 에셋, ZIP 내부 경로 탈출(`../`), ZIP 중복명 등을 정적 검사한다.
- ZIP 전체 데이터 규모와 엔트리 수를 제한한다. 이 제한은 보안 및 시스템 안전을 위한 도구 정책이지 카카오 공식 제한 수치가 아니다.
- ZIP의 CRC 검증으로 읽기 손상 여부를 확인하지만 iOS 카카오톡 실제 렌더링을 검증하지는 못한다.

## 6. 실기기 적용

- iPhone의 카카오톡에서 `.ktheme` 파일을 열어 테마를 추가·적용한다.
- 앱 버전과 화면별 적용을 실제 단말에서 확인한다.
- 성공 여부는 `정적 통과`, `설치 통과`, `렌더링 통과`로 분리해서 기록한다.
